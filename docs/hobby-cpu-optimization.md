# 免費方案 CPU 優化（2026-11-03）

以 GitHub main 8e1c95a 為基準；Vercel 正式部署同一 commit，目前 live:false。
未合併、未升級、未購買、未開啟 Observability Plus、未建立外部付費資源。
本次更改不能解除平台暫停；依使用者提供的通知，暫停至 2026-12-03。

## 已確認的負載來源

- 首頁個股、加權、夜盤交易時段每秒輪詢；非交易時段每 30 秒。每支 API 每小時最多 3600 次。
- 全球市場每 15 秒；法人／籌碼每 15 秒；盤前即時分析與產業每 30 秒，新聞每分鐘。
- 分析每次並行請求行情、融資、法人、期權、新聞、產業與回測。抓取原文的 Next fetch 快取不會消除 JSON/HTML 解析與回測計算。
- 倉位回測在 252 個測試日中，對相同 fitEnd 重複選參數；同一月份的模型原本重算約 21 次。
- Yahoo 每筆歷史日期重新建立 Intl.DateTimeFormat。
- 部分分鐘歷史在分頁隱藏時仍輪詢；focus/online 可連續觸發請求；多數 loader 吞掉錯誤，輪詢無法退避。
- 健康檢查每小時探測 14 個端點（含多個重型端點）。

以上是程式碼證據，並非 Vercel 各路徑實測 CPU 排行。唯讀 observability 查詢回傳 400 bad_request；目前工具的 schema 僅列指標，未取得足以確認各路徑的查詢維度。最近 runtime logs 無資料，不能宣稱沒有歷史錯誤或用量為零。

## 更改與更新頻率

| 項目 | 原本 | 現在 |
|---|---|---|
| 個股／加權／夜盤，交易時段 | 1 秒 | 10 秒 |
| 同上，非交易時段 | 30 秒 | 5 分鐘 |
| 全球市場 | 15 秒 | 60 秒 |
| 法人／籌碼／收盤 | 15 秒 | 5 分鐘 |
| 盤前即時分析／產業 | 30 秒 | 5 分鐘 |
| 新聞 | 60 秒 | 5 分鐘 |
| 分鐘歷史 | 隱藏也輪詢 | 可見才輪詢，避免重疊 |
| 正式站健康檢查 | 每小時 | 平日每日一次（台北 09:23） |

報價仍按來源更新，保留 quoteTime／延遲／資料日，不保證每次輪詢都有新報價。
成功後切回畫面可提早刷新，但 5 秒內事件合併；失敗依倍增間隔退避，最長 30 分鐘，focus 不繞過錯誤退避。

- 有界的暖實例回應快取＋同時請求去重：行情 10 秒、全球 60 秒、產業／新聞／分析 5 分鐘；HTTP 錯誤短暫快取 15 秒。
- 資料逾期後必須重新計算，不偷偷以舊成功結果代替新結果。回應保留原始時間戳。
- 盤前分析每次仍先驗證登入；只有與使用者無關的研究內容共用，HTTP 維持 private,no-store。封存／capture 不進共用快取，也不繞過封存時窗。
- 回測依 completedDate 快取一小時，失敗 30 秒重試；訓練同一 fitEnd 只做一次，算法與結果保持相同。
- Yahoo 依 symbol 去重抓取與解析、依 timezone 重用有界 formatter；每日籌碼來源原文快取 5 分鐘。
- 沒有新增排程；保留 GitHub 08:45 盤前 capture、16:30 盤後驗證，以及產業盤後補檔。Vercel 原有每日 08:30 cron 只讀取快照，本次不改動其行為。

## 驗證與限制

詳見 cpu-benchmark.json：1000 根合成日 K，與修改前基準輸出完全一致；單次本機計時約 6872 ms → 510 ms，再讀快取約 0.014 ms，兩次只抓取一次。這是本機單次牆鐘時間，不能當成正式環境 Active CPU 節省百分比。

新增測試涵蓋並行去重、回應可各自讀取、快取期限、錯誤冷卻、key 隔離、輪詢退避、回測基準相等與登入檢查不被熱快取繞過。

快取只在同一暖實例內共用，冷啟動／不同區域可能各自重算；CDN 對公開端點另有短暫快取。沒有承諾流量無限時仍不超額。暫停恢復後應以相同時段／流量比較 Active CPU、invocation count、各端點錯誤率和資料延遲；僅使用可免費取得的資料，不啟用 Plus。
